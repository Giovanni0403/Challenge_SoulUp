1. Objetivo e escopo do projeto

A EcoSoul incentiva o uso de ônibus, metrô e trem. Cada viagem registrada gera ECO Points, e o sistema mostra quanto CO₂ aquela viagem evitou em relação ao mesmo trajeto feito de carro.

Esta entrega é a API RESTful em Java com Spring Boot que dá suporte ao front-end (React + Vite + TypeScript). Ela guarda os usuários e as viagens de cada um no banco Oracle da FIAP, valida os dados com regras de negócio e devolve respostas em JSON com os códigos HTTP corretos.

Escopo desta sprint

  • CRUD completo de usuários e de viagens, com relacionamento 1 usuário : N viagens.
  • Arquitetura em camadas: Model → DAO (com ConnectionFactory) → BO → Resource.
  • Tratamento centralizado de exceções e liberação de acesso do front-end com CorsFilter.
  • Integração com o front-end publicado na Vercel e deploy da API em servidor de aplicação (Render).

Fora do escopo: validação automática do trajeto por GPS/IA e a troca de pontos por benefícios. Essas funções aparecem no protótipo do front-end como proposta futura.

2. Principais funcionalidades

FuncionalidadeO que faz
Cadastro de usuáriosCria, lista, consulta, edita e exclui usuários. O e-mail é único (409 se repetido).
Registro de viagensCria, lista, consulta, edita e exclui viagens de ônibus, metrô ou trem, sempre ligadas a um usuário existente.
Histórico por usuárioGET /usuarios/{id}/viagens devolve só as viagens daquela pessoa.
Regras de negócio (BO)Origem e destino de 2 a 80 caracteres e diferentes entre si; distância entre 0 e 500 km; data não pode estar no futuro; nome de 3 a 100 caracteres; e-mail válido; usuário com viagens não pode ser excluído.
Erros padronizadosToda falha volta em JSON { status, erro, mensagem }, que o front-end mostra para o usuário.
Integração com o frontCorsFilter libera o acesso do site; o front calcula ECO Points (10 por km) e CO₂ evitado a partir dos dados da API.

5. Modelo Entidade-Relacionamento (MER)

Duas entidades no Oracle. Um usuário registra zero ou muitas viagens; cada viagem pertence a exatamente um usuário (chave estrangeira ID_USUARIO).

Restrições

RestriçãoRegra
PK_ECO_USUARIO / PK_ECO_VIAGEMChaves primárias geradas automaticamente (IDENTITY).
UN_ECO_USUARIO_EMAILNão pode haver dois usuários com o mesmo e-mail.
FK_ECO_VIAGEM_USUARIOToda viagem aponta para um usuário existente.
CK_ECO_VIAGEM_TRANSPORTETransporte só pode ser ONIBUS, METRO ou TREM.
CK_ECO_VIAGEM_DISTANCIADistância maior que 0 e no máximo 500 km.

Legenda: PK chave primária · FK chave estrangeira · UK valor único. O script completo está em sql/script.sql.

6. Diagrama de classes

Pacote base: br.com.fiap.ecosoul. O diagrama foi dividido em quatro partes para ficar legível.

6.1 Camada Model: entidades e associação

Viagem tem um atributo usuario: Usuario (associação muitos-para-um) e um transporte do tipo enumerado TipoTransporte.

Nas próximas páginas: 6.2 exceções e infraestrutura; 6.3 e 6.4 as camadas Resource → BO → DAO → ConnectionFactory de cada entidade. Setas tracejadas indicam dependência (uma classe usa a outra); o triângulo vazado indica herança/implementação.

6.2 Exceções (herança) e infraestrutura

As quatro exceções do projeto herdam de RuntimeException. O TratadorDeErros trata todas elas e devolve o status HTTP correto, e o CorsFilter implementa a interface Filter para liberar o acesso do front-end.

6.3 Camadas de Usuário

UsuarioResource recebe a requisição, UsuarioBO valida e aplica as regras, e UsuarioDAO executa o SQL. O UsuarioBO também usa o ViagemDAO para impedir a exclusão de um usuário que tem viagens.

6.4 Camadas de Viagem

Mesmo fluxo para viagens. O ViagemBO usa o UsuarioDAO para conferir se o usuário dono da viagem existe antes de gravar.

7. Procedimentos para rodar a aplicação

Ferramentas e versões

FerramentaVersão / observação
Java JDK21 ou superior (testado com JDK 25)
Spring Boot4.1.2 (dependências: Spring Web MVC e driver Oracle ojdbc17)
MavenMaven Wrapper incluso (mvnw / mvnw.cmd), não precisa instalar
IDEIntelliJ IDEA (recomendado) ou VS Code com Extension Pack for Java
Banco de dadosOracle da FIAP (oracle.fiap.com.br:1521/ORCL) + Oracle SQL Developer
Front-end (opcional)Node.js 20.19+ ou 22.12+ e npm

Passo a passo

  1. Banco: abra o SQL Developer, conecte com o usuário rmXXXXXX e execute EcoSoul-API/sql/script.sql (F5). Ele cria as tabelas e insere dados de exemplo.
  2. Importar no IntelliJ: File → Open e selecione a pasta EcoSoul-API (onde está o pom.xml). Aguarde o Maven baixar as dependências.
  3. Credenciais: em Run → Edit Configurations → EcoSoulApiApplication → Environment variables, adicione DB_USER=rmXXXXXX;DB_PASSWORD=sua_senha. A senha nunca fica no código.
  4. Executar: rode a classe EcoSoulApiApplication, ou no terminal, dentro de EcoSoul-API: 
    mvnw.cmd spring-boot:run        (Windows)
./mvnw spring-boot:run          (Linux/macOS)
  5. Testar: acesse http://localhost:8080/viagens e http://localhost:8080/usuarios no navegador, ou use Postman/Insomnia com os endpoints da seção 3.
  6. Front-end (opcional): na pasta EcoSoul, crie um arquivo .env com VITE_API_URL=http://localhost:8080 e rode npm i e npm run dev.

Deploy

A API é publicada no Render usando o Dockerfile da pasta EcoSoul-API (Root Directory EcoSoul-API, runtime Docker), com DB_USER e DB_PASSWORD cadastrados como variáveis de ambiente.
